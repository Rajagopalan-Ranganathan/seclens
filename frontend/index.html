The seclens Score

Every product gets a 0–100 security score (higher = more secure) and a letter grade from A+ to F, computed from six factors:

Factor Weight What it measures
KEV Exposure 20% Ratio of CVEs on the CISA Known Exploited Vulnerabilities list — fewer = higher score
Patch Velocity 20% Median days between CVE publication and fix — faster patching = higher score
Unpatched Ratio 20% Percentage of CVEs with no known fix — fewer unpatched = higher score
Average Severity 15% Mean effective CVSS — patched CVEs count at half severity since active risk is reduced
Exploit Likelihood 15% Mean EPSS score — lower probability of real-world exploitation = higher score
Vulnerability Density 10% Total CVEs relative to product age (log scale) — heavily-audited products aren't penalized

Product Data Sources

  • NVD — CVE vulnerability data, CVSS scores, CPE product identifiers, and patch version info
  • EPSS — Exploit Prediction Scoring System, probability of real-world exploitation within 30 days
  • CISA KEV — Known Exploited Vulnerabilities catalog, confirmed actively exploited CVEs

GitHub Project Score

When you paste a GitHub repository URL, seclens analyzes the project's dependencies and repository security posture. The score is computed from three factors:

Factor Weight What it measures
Dependency Risk 50% Vulnerable dependencies, severity of their CVEs, and whether fixes are available
Repo Posture 30% Branch protection, secret scanning, code scanning, dependency updates (Dependabot/Renovate/Konflux), license, and maintenance activity
Supply Chain 20% Pinned dependency versions and direct vs. transitive vulnerability exposure

Project Data Sources

  • GitHub SBOM API — full dependency graph including transitive deps (falls back to manifest parsing)
  • OSV.dev — Open Source Vulnerabilities database for dependency CVE lookup
  • GitHub REST API — repository metadata, branch protection, security features
